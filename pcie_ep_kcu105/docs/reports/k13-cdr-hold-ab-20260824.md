# K13 Recovery.Speed CDR-hold A/B 构建记录（2026-08-24）

## 目的

只改变 `Recovery.Speed` 期间的 `as_cdr_hold_req`，验证它是否是 K13
Gen1→Gen3 时 QPLL1 失锁的必要条件。PHY rate contract、`phy_rate_cmd=2`、
TX Electrical Idle、GT rate/reset 路径和 ILA 探针均保持不变。

## RTL 开关

新增参数 `K13_CDR_HOLD_FORCE_LOW`，默认值为 `0`，因此默认生产行为不变：

```verilog
as_cdr_hold_req = (K13_CDR_HOLD_FORCE_LOW == 0) &&
                  (ltssm_state == RECOVERY_SPEED);
```

构建环境变量 `K13_CDR_HOLD_FORCE_LOW=1` 才会生成本 A/B 的低电平版本。
原有 `K13_CDR_HOLD_RECOVERY` 仅保留为构建变体标记，不再被误认为是 RTL
行为开关。

## 上板判据

用同一 Root Port retrain 流程和同一 ILA 触发器抓取：

- `dbg_k13_top[0]`（`as_cdr_hold_req`）应在切速窗口为 `0`；
- `phy_rate/rxrate` 仍应从 `0` 变为 `2`；
- 记录 `QPLL1RESET`、`QPLL1LOCK`、`QPLL1REFCLKLOST`、`QPLL1FBCLKLOST`；
- 记录 `PCIERATEGEN3`、`PCIEUSERRATESTART/DONE`、`PCIEUSERGEN3RDY`、
  `PHYSTATUS` 和 `PCIERATEIDLE`。

若只把 CDR hold 拉低后 QPLL1LOCK 恢复并出现 PHYSTATUS，才能确认 CDR hold
时序是主要根因。若 QPLL1LOCK 仍不恢复，则应回到 QPLL1 参考/反馈时钟、PLL
选择和 GT rate-change reset 时序分析。

## 2026-08-24 上板结果

实际烧录并抓取了上述低 CDR-hold A/B bit。KCU105 xcku040 使用
`localhost:3121` hw_server，PIPE/Core ILA 均成功触发；有效 PIPE 波形为：

```text
capture: fpga/kcu105/build_k13_gen3_ila_cdr_hold_low_gt_primitive_qpll_prereq/capture/20260824_151000_u_ila_pipe.csv

sample 512 : Recovery active，dbg_k13_top[0]=0
sample 3307: phy_rate=2，rxrate=2，TXEI=1，dbg_k13_top[0]=0
sample 3316: PCIERATEQPLLRESET=1，GTHE3 qpll1reset=1，QPLL1LOCK 1->0
sample 3321: PCIERATEQPLLRESET/GTHE3 qpll1reset 释放
sample 4095: QPLL1LOCK=0，PHYSTATUS=0，PCIEUSERGEN3RDY=0，PCIEUSERRATEDONE=0
```

低 CDR-hold 版本的 `as_cdr_hold_req` 在整个采样窗口均为 0；因此这不是
“CDR hold 没有释放”导致的充分解释。对照生产基线波形（CDR hold=1）虽然
切速起点不同，但同样在 QPLL reset 后没有重新锁定，A/B 结果排除了 CDR hold
作为当前 QPLL1 失锁的唯一根因。

主机侧重启并重新枚举后，Endpoint `01:00.0` 仍报告
`LnkSta: Speed 2.5GT/s (downgraded), Width x1`，且 `LnkSta2` 的
`EqualizationComplete-`，与 ILA 中 QPLL1LOCK 未恢复、未产生 PHYSTATUS 相符。

### 当前结论和下一步

K13 的切速请求已经送达 GT（RATE=2、QPLL reset 脉冲真实出现），但 QPLL1
没有完成重锁；因此应优先检查：

1. QPLL1 的参考时钟/反馈时钟丢失状态和实际频率；
2. QPLL1 选择、QPLL1RESET 与 `PCIERATEQPLLRESET` 的时序契约；
3. GT primitive 中 `QPLL1REFCLKLOST`、`QPLL1FBCLKLOST`、`QPLL1LOCK` 在 reset
   前后的稳定值，以及是否存在 IP 手册定义的 rate-change unexpected-error；
4. 只有 QPLL1LOCK 恢复后仍没有 PHYSTATUS，才继续分析 PHY rate contract 或
   RX EQ/TS 协议。
